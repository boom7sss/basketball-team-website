# 内容维护说明

日常交接优先阅读 `docs/HANDOVER.md`。本文是后台内容维护细则，适合负责日常更新的同学按需查阅。

## 后台入口

本地后台：

```text
http://localhost:3000/admin
```

本地开发环境如果没有设置 `ADMIN_PASSWORD`，会使用本地兜底密码。正式线上密码以服务器环境变量为准，并通过可信渠道交接。

正式线上不要使用本地兜底密码，也不要把正式密码写进文档或 GitHub。

## 保存规则

后台修改后需要点击：

```text
保存全部
```

保存后的公开内容会写入：

```text
data/site-data.json
```

报名信息也保存在同一个文件里，但不会通过 `GET /api/site` 暴露给前台。

## 日常维护速查

后续负责人日常维护主要在后台完成：

- 更新队员：进入“队员阵容”，修改姓名、号码、状态、位置、简介、照片地址等，最后点击“保存全部”。
- 更新赛程：进入“赛程战绩”，未比赛填 `upcoming`，已比赛填 `finished` 并补比分和摘要。
- 更新新闻：进入“新闻动态”，填写标题、日期、封面、轮播照片、摘要和正文。
- 更新图片：在带有“封面地址、照片地址、图片地址、轮播照片地址”的字段旁点击“上传”，上传后点击“保存全部”。
- 更新视频：可以在后台上传视频并保存；如果视频较大，推荐单独上传到服务器同路径，再在后台填写以 `/assets/` 开头的视频地址。
- 更新招新群号：进入“招新信息 -> 咨询说明”，填写真实 QQ 群号，保存后报名成功弹窗会自动显示新文案。

## 上传素材

后台中带有“封面地址、照片地址、图片地址、素材地址、轮播照片地址”的字段旁会显示上传按钮。

支持格式：

- 图片：jpg、jpeg、png、webp
- 视频：mp4、webm、mov

上传规则：

- 图片会自动转成 `.webp`
- 图片最大边控制在 1920px 内
- 图片质量为 86
- 视频不会自动压缩，也不会自动生成 `-web.mp4`
- 上传后会自动填入 `/assets/uploads/...` 地址
- 上传后仍然需要点击“保存全部”

上传后的目录大致为：

```text
public/assets/uploads/news       # 新闻封面和新闻轮播照片
public/assets/uploads/players    # 队员照片
public/assets/uploads/gallery    # 影像中心图片和视频
public/assets/uploads/sponsors   # 赞助商封面
public/assets/uploads/general    # 其他未归类素材
```

负责人只需要在后台上传并保存，不需要手动改文件名。上传后后台字段里看到的 `/assets/uploads/...` 就是前台可访问地址。

## 后续新增视频处理规则

当前最稳的维护规则是：

```text
图片：后台自动处理，上传后会转成 WebP。
视频：人工判断和压缩，后台不会自动压缩。
```

如果后续负责人上传新视频，建议按下面流程处理：

1. 先看视频大小、分辨率和码率。
2. 如果是大视频，先用 `ffmpeg` 生成 `-web.mp4` 网页播放版。
3. 人工打开网页播放版看画质和播放是否流畅。
4. 画质可以接受后，再把后台“素材地址”改成 `-web.mp4`。
5. 原视频先保留，方便回滚。

简单判断标准：

```text
小于 10MB，720p/1080p，播放不卡：可以先不压。
10-30MB：先看实际播放是否卡，必要时压缩。
超过 30MB，尤其是 4K / HEVC / 高码率：建议压成 web 版。
超过 100MB：基本建议压缩；后续访问量大时再考虑 COS / OSS / CDN。
```

不建议现在做“后台上传视频后自动压缩”，原因是：

- 视频压缩很吃 CPU，当前 2 核 / 2GB VPS 容易卡。
- 上传大视频后，后台请求可能等待很久甚至超时。
- 自动压缩失败处理会让后台逻辑变复杂。
- 现在人工判断更稳，也更适合毕业交接。

因此当前维护原则是：

```text
图片后台自动处理；视频人工判断和压缩。
```

## 手动填写素材地址

如果不使用上传按钮，手动填写时应使用网站路径，例如：

```text
/assets/gallery/highlights/photos/highlight-photo-1.webp
```

不要填写 Windows 绝对路径，例如：

```text
D:\球队网站\影像素材\比赛集锦\照片\xxx.jpg
```

浏览器访问的是服务器公开路径，不认识你电脑上的绝对路径。

如果手动把文件放进项目，请放在 `public/assets` 下面，并填写以 `/assets/` 开头的路径。建议沿用下面的分类：

```text
public/assets/players
public/assets/news
public/assets/gallery/highlights/photos
public/assets/gallery/highlights/videos
public/assets/gallery/team-photos
public/assets/gallery/training
public/assets/gallery/life
```

图片建议使用 `.webp`。视频可以先使用 `.mp4`，但不要上传过大的原始视频；正式运营后建议压缩成网页播放版，或放到对象存储 / CDN 后再填写外部可访问地址。

视频部署特别说明：

- 视频文件没有被 Git 跟踪。
- 如果代码通过 Git 部署，视频需要单独上传到服务器相同目录。
- 比赛视频目录：`public/assets/gallery/highlights/videos`
- 训练视频目录：`public/assets/gallery/training`
- 生活视频目录：`public/assets/gallery/life`
- 数据里写的是 `/assets/...` 路径，只要服务器同路径有对应视频，前台就能播放。

## 报名通知

当前报名表提交后，会写入 `data/site-data.json` 的 `applications`，后台“报名管理”可以查看、修改状态、填写备注和删除记录。报名同学提交成功后，页面会提示加入招新 QQ 群，群号文案来自后台“招新信息 -> 咨询说明”。

当前不会自动通知负责人：

- 不会自动发邮件。
- 不会自动发微信、短信、企业微信或飞书消息。
- 前台提交成功会弹出招新 QQ 群提示，但不会主动给负责人推送消息。

上线前临时方案：

- 让报名同学先加入招新 QQ 群，入群备注“姓名+年级+专业”。
- 指定一名负责人每天固定进入 `/admin` 查看“报名管理”。
- 招新集中期建议每天 2 次检查，例如中午和晚上训练前。
- 把后台地址、正式后台密码保存在队内可信渠道，不要发到公开群。
- 若报名特别集中，可以在群公告里提醒负责人处理后台报名。

后续正式方案：

- 在 `server/server.mjs` 的 `POST /api/applications` 保存成功后，增加通知调用。
- 简单优先级建议：企业微信机器人或飞书 webhook，其次是 SMTP 邮件。
- 通知配置使用环境变量，例如 `APPLICATION_NOTIFY_WEBHOOK`、`SMTP_HOST`、`SMTP_USER`、`SMTP_PASS`，不要写进代码。
- 通知失败时不要影响报名保存，只记录错误并让后台仍能看到报名。
- 增加自动测试，覆盖“报名保存成功”和“通知接口失败但报名不丢失”。

## 后台密码与安全

当前后台是单管理员密码，登录成功后浏览器保存一个 12 小时有效的管理令牌。这个方案适合学院篮球队首版上线和小范围维护，但有几个风险：

- 多个人共用同一个密码，无法区分是谁修改了内容。
- 如果继续使用默认密码，知道项目的人可能尝试登录。
- 如果没有设置 `SESSION_SECRET`，服务重启后旧令牌会失效，且长期运营不够稳定。

上线前建议：

- 必须设置正式 `ADMIN_PASSWORD`，不要使用默认密码。
- 必须设置一串较长随机 `SESSION_SECRET`。
- 后台只发给少数负责人，密码不要公开写在群公告或网页里。
- 使用 HTTPS 部署，避免密码在网络中明文传输。
- 负责人离队或毕业后及时更换 `ADMIN_PASSWORD`。

后续长期方案：

- 增加多管理员账号，至少区分“内容维护”和“报名管理”。
- 增加修改记录，例如保存时间、操作者、修改模块。
- 重要操作如删除报名记录、删除素材，增加二次确认或保留回收记录。

## 当前仍写死在代码里的内容

以下内容目前不在后台管理中：

- 顶部导航栏目：已在 `data/site-data.json` 的 `navigation` 中维护，`public/app.js` 只保留兜底默认值。
- 影像中心四个大板块：已在 `data/site-data.json` 的 `gallerySections` 中维护，`public/app.js` 只保留兜底默认值。
- 比赛集锦下的“比赛照片/比赛视频”：已在 `data/site-data.json` 的 `gallerySubsections` 中维护，`public/app.js` 只保留兜底默认值。
- 后台栏目顺序：`adminTabs`
- 页面文案默认值：`pageDefinitionDefaults` / `pageDefinitions()`
- 部分新增条目的默认内容：`factories`
- 登录页说明文字

不建议普通内容负责人直接修改：

- `adminTabs`：控制后台栏目顺序和入口。
- `schemas`：控制后台字段类型。
- `factories`：控制新增条目的默认内容。

建议后续继续优化：

- 如果需要后台可视化维护导航和影像栏目，可再增加“网站结构”后台页。
- 页面结构型内容迁移到 JSON，长文章可考虑 Markdown
- 后台字段配置仍可保留在代码中，避免非技术负责人误改字段结构

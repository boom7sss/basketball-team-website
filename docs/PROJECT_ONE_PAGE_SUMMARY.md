# 项目一页总结

这是一个为太原理工大学人工智能学院篮球队建设的官网项目。它解决的问题是：球队需要一个可以公开展示球队信息、队员阵容、赛程战绩、新闻动态、照片视频、招新报名和赞助合作信息的网站，同时后续负责人不改代码也能通过后台持续维护内容。

## 核心功能

前台面向访问者，负责展示内容：主页、球队介绍、赛程战绩、新闻列表和详情、队员阵容和详情、影像中心、招新报名、赞助合作和联系方式。

后台面向维护者，负责更新内容：后台登录、球队资料编辑、队员维护、赛程维护、新闻维护、图片/视频上传、招新信息维护、报名记录查看和处理。后台保存后，内容会写入服务器上的运行时数据文件。

## 技术栈

- 前端：原生 HTML、CSS、JavaScript。`public/index.html` 是入口，`public/app.js` 负责路由、页面渲染、后台交互和 API 调用，`public/styles.css` 负责样式。
- 后端：Node.js 内置 HTTP Server。`server/server.mjs` 处理公开 API、后台登录、后台保存、上传和报名。
- 数据：JSON 文件。`data/site-data.seed.json` 是初始快照，线上真实运行数据是服务器上的 `data/site-data.json`。
- 图片处理：`sharp`。后台上传图片后自动转成 WebP，并限制尺寸，减少网页体积。
- 测试：Node.js 内置 test runner。`npm test` 覆盖数据、API、上传、报名和页面关键契约。
- 当前未使用：Vue、React、Next.js、数据库、多账号权限系统、对象存储、CDN。

## 部署方式

项目已经部署到香港 VPS。服务器运行 Ubuntu，代码从 GitHub 拉取到 `/var/www/basketball-team-website`。Node 服务由 pm2 管理，服务名是 `basketball-team-website`。Nginx 对外提供 HTTP 访问，把页面和 API 请求转发给 Node，同时直接托管 `/assets/` 静态资源。

GitHub 负责保存代码、文档和版本历史；VPS 负责长期运行网站、保存运行时数据、保存上传文件和视频；pm2 负责让 Node 服务持续在线；Nginx 负责公网入口、反向代理、静态资源缓存和视频分段访问。

## 交接方式

交接文档入口是 `docs/DOCUMENTS_GUIDE.md` 和 `docs/HANDOVER.md`。实际交接信息填写在 `docs/HANDOVER_INFO_TEMPLATE.md`。常用运维命令在 `docs/OPS_COMMANDS.md`。内容维护看 `docs/CONTENT_MANAGEMENT.md`。备份恢复看 `docs/BACKUP_AUTOMATION.md`。域名和 HTTPS 后续处理看 `docs/DOMAIN_HTTPS_TODO.md`。

交接时不能把真实后台密码、服务器登录密码、SSH 私钥、`SESSION_SECRET`、云服务账号密码写进 GitHub 或文档。密码和密钥只通过可信渠道单独交接。下一届负责人应该从 GitHub clone 仓库，不要直接接收包含 `.git` 的本地压缩包。

## 后续重点

当前网站已经可以使用，但还没有绑定正式域名和 HTTPS。下一届技术负责人优先处理域名和 HTTPS：申请学院二级域名或购买正式域名，把 A 记录指向服务器 IP，再按文档配置 `certbot + nginx`。其次是负责人更换后及时更换后台密码、每月下载异地备份、根据访问量决定是否迁移视频到对象存储或 CDN。

长期优化方向包括：后台登录限速、多管理员权限系统、报名通知、数据库替代 JSON 文件、媒体管理界面、对象存储和 CDN。

## 个人收获

这个项目让我完整经历了从本地开发到线上部署、从页面展示到后台维护、从 GitHub 管理代码到 VPS 运维、从 Nginx 反向代理到 pm2 常驻运行、从视频优化到自动备份、从功能完成到最终交接的全过程。

最重要的经验是：一个能交付的项目不只是“页面做出来”，还要考虑真实数据怎么保存、密码怎么保护、大文件怎么管理、服务器怎么运行、出问题怎么排查、备份怎么恢复、下一任负责人怎么接手。这个项目把“本地能跑”推进到了“线上能用、能维护、能交接”的状态。
